# Education Administration Copilot V1 - Frontend 구현 계획

> 상태: **완료**  
> 완료일: 2026-06-08  
> 빌드: `frontend/` — `npm run build` 성공

## 목표

백엔드 RAG 시스템(FastAPI + Supabase + GPT-4.1 Mini)이 정상 동작하는 상태에서

사용자가

* **현재 RAG Knowledge Base 규모·문서 목록 확인**
* 공문(PDF/HWPX) 업로드
* 질문 입력
* AI 답변 확인
* 출처 확인

을 할 수 있는 최소 기능의 MVP 프론트엔드를 구축한다.

### 핵심 가치 체인

```text
공문 업로드
  ↓
업무매뉴얼 / 법령 / 행정규칙 검색
  ↓
GPT 답변 + 출처
```

프론트엔드는 이 흐름을 **시연·면접에서 한눈에 이해되도록** 보여주는 것이 목표이다.

---

# 개발 원칙

본 프로젝트의 핵심은 AI/RAG이다.

프론트엔드는 시연용 MVP 수준으로만 구현한다.

프론트 개발 시간은 전체 프로젝트의 10~20% 이내로 제한한다.

과도한 디자인·과설계는 하지 않는다. **기능 우선, 디자인 최소.**

# V1 / V2 범위

## V1 (이번에 구현)

| 기능 | 우선순위 | 비고 |
|------|----------|------|
| `GET /documents` — 문서 목록·통계 | ⭐⭐⭐⭐⭐ | KB 규모 시연에 필수 |
| 좌측 Knowledge Base 패널 | ⭐⭐⭐⭐⭐ | 카테고리별 문서 수, Chunk 수 |
| 채팅 + 출처 + 로딩 | ⭐⭐⭐⭐⭐ | `POST /chat` (백엔드 완료) |
| 공문 업로드 | ⭐⭐⭐⭐⭐ | `POST /documents/upload` (백엔드 추가 필요) |

## V2 (이번에 구현하지 않음)

| 기능 | 우선순위 | 비고 |
|------|----------|------|
| 드래그앤드롭 등록 여부 확인 | ⭐⭐ | 사용자 실사용 가치 낮음, ROI 낮음 |
| 중복 업로드 방지 | ⭐⭐ | V2에서 업로드와 함께 검토 |

### V1에서 제외한 이유 (드래그 등록 확인)

파일 드래그 → 등록 여부 확인은 시연에서 잠깐 반응할 뿐, 프로젝트 핵심 스토리와 무관하다.

면접·시연에서 설득력 있는 것은 다음이다.

* 현재 KB 규모 (문서 수, Chunk 수)
* 카테고리별 문서 수 (업무매뉴얼 / 법령 / 행정규칙)
* 답변 + 출처

# 기술 스택

## Framework

* React
* Vite
* TypeScript

## UI

* Tailwind CSS
* shadcn/ui

Tailwind는 Utility 기반 CSS 프레임워크이며, shadcn/ui는 Tailwind 위에서 동작하는 React 컴포넌트 모음이다. shadcn/ui는 컴포넌트 코드를 프로젝트 내부로 복사하여 사용하는 방식이라 수정이 자유롭다.

## HTTP

* Axios
* API URL: 환경변수 `VITE_API_URL` (기본 `http://localhost:8000`)

## 개발 환경

프론트(Vite `localhost:5173`)와 API(`localhost:8000`) 분리 실행 시 **CORS 또는 Vite proxy** 설정 필요.

# 최종 목표

면접·시연에서 다음이 **한 화면에** 보이는 MVP:

```text
[RAG Knowledge Base]          [채팅]
업무매뉴얼 156 · 법령 923      질문 → 답변
총 Chunk 12,451               출처 (파일명, 장/절, similarity)
최근 등록 문서
[공문 업로드]
```

사용자가 공문을 업로드하고 질문하면, FastAPI RAG 서버가 검색·답변을 수행하고, 프론트엔드는 **KB 규모 · 답변 · 출처**를 함께 보여준다.

