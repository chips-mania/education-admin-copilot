# Education Administration Copilot V1 구현 계획서

## 프로젝트 목표

학교 업무매뉴얼, 교육 관련 법령, 행정규칙, 법령해석례를 기반으로 질의응답이 가능한 교육행정 AI Copilot을 구축한다.

V1의 목표는 Retrieval 성능 비교를 위한 Baseline 구축이다.

본 버전은 Dense Vector Search 기반 RAG만 구현하며, 이후 Hybrid Search, Reranker, Agent Workflow 성능 비교를 위한 기준점 역할을 수행한다.

---

# 개발 원칙

1. 한 번에 전체 시스템을 구현하지 않는다.
2. 각 단계 완료 후 반드시 테스트를 수행한다.
3. 테스트 통과 후 다음 단계로 진행한다.
4. 실패 시 원인 분석 후 수정한다.
5. 모든 단계는 독립적으로 실행 가능해야 한다.
6. 콘솔 로그를 충분히 출력한다.
7. 각 Step 완료 시 테스트 결과를 문서화한다.

# 아키텍처 (FastAPI + Supabase)

FastAPI와 Supabase는 역할이 분리된 조합이다.

| 구분 | FastAPI | Supabase |
|------|---------|----------|
| 역할 | HTTP API, RAG 파이프라인 조율 | 문서·벡터 저장 및 검색 |
| 담당 | `POST /chat` 요청/응답 | `documents`, `chunks` 테이블 |
| 검색 | RPC 결과를 받아 LLM에 전달 | `match_documents()` RPC로 Top-K 검색 |
| 임베딩/LLM | bge-m3, OpenAI 호출 | 저장만 담당 |

## 요청 흐름

```text
사용자
  ↓ POST /chat
FastAPI
  ↓ 질문 임베딩 생성 (bge-m3)
  ↓ supabase.rpc("match_documents") 호출
Supabase (PostgreSQL + pgvector)
  ↓ Top-K Chunk 반환
FastAPI
  ↓ GPT-4.1 Mini 답변 생성
  ↓ answer + sources 응답
사용자
```

## DB 접근 규칙

* 로컬 PostgreSQL 직접 설치·연결하지 않는다.
* SQLAlchemy 사용하지 않는다.
* Supabase Python Client만 사용한다.
* pgvector 검색은 Supabase RPC Function으로만 구현한다.

# STEP 2

## Supabase 데이터베이스 스키마 생성

### 목표

Supabase SQL Editor에서 테이블 및 벡터 검색 RPC 생성

### source_type 허용 값

```text
manual        → data/raw/manuals/
law           → data/raw/laws/
regulation    → data/raw/regulations/
interpretation→ data/raw/interpretations/
```

### documents

```sql
create table documents (
    id bigint generated always as identity primary key,
    title text not null,
    source_type text not null,
    file_name text not null,
    file_path text not null,
    created_at timestamptz default now(),

    constraint documents_source_type_check check (
        source_type in ('manual', 'law', 'regulation', 'interpretation')
    )
);
```

### chunks

```sql
create table chunks (
    id bigint generated always as identity primary key,
    document_id bigint not null references documents(id) on delete cascade,
    chunk_no integer not null,
    content text not null,
    source_type text not null,
    metadata jsonb default '{}'::jsonb,
    embedding vector(1024),

    constraint chunks_source_type_check check (
        source_type in ('manual', 'law', 'regulation', 'interpretation')
    )
);
```

### metadata 예시

```json
{
  "chapter": "제6편 복무",
  "section": "출장",
  "source": "업무매뉴얼",
  "page": 123
}
```

### 인덱스

```sql
create index chunks_embedding_idx
    on chunks using hnsw (embedding vector_cosine_ops);

create index chunks_metadata_idx
    on chunks using gin (metadata);
```

### RPC Function (match_documents)

```sql
create or replace function match_documents(
    query_embedding vector(1024),
    match_count int default 5,
    match_threshold float default 0.5
)
returns table (
    id bigint,
    document_id bigint,
    chunk_no integer,
    content text,
    source_type text,
    metadata jsonb,
    similarity float,
    document_title text,
    file_name text,
    file_path text
)
language sql stable
as $$
    select
        c.id,
        c.document_id,
        c.chunk_no,
        c.content,
        c.source_type,
        c.metadata,
        1 - (c.embedding <=> query_embedding) as similarity,
        d.title as document_title,
        d.file_name,
        d.file_path
    from chunks c
    join documents d on d.id = c.document_id
    where c.embedding is not null
      and 1 - (c.embedding <=> query_embedding) > match_threshold
    order by c.embedding <=> query_embedding
    limit match_count;
$$;
```

### 검증

Supabase Table Editor 또는 SQL Editor에서 조회

```sql

select * from chunks;
```
